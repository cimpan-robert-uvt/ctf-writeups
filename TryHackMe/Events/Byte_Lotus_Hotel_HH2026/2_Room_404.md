# Day 2 - Room 404

**Difficulty:** Very easy  
**Category:** Web enumeration / information disclosure

**Summary:** This room focuses on a very common and dangerous web misconfiguration: an exposed `.git` directory. By using directory fuzzing tools, we discover the hidden repository, download its contents using a specialized tool, and recover sensitive information (the flag) left behind by the developers.

## 1. Reconnaissance

We started by scanning the target machine using `nmap` to identify open ports and running services. The scan revealed that the machine is hosting a web application on an alternative HTTP port: `8080`.

## 2. Web enumeration

Visiting the web page directly doesn't give us much information on the surface. To dig deeper and find hidden directories or files, we used a fast web fuzzing tool called `feroxbuster`.

We ran the tool against the target URL using a standard wordlist:

```
feroxbuster -u http://10.114.129.227:8080 -w /usr/share/wordlists/SecLists/Discovery/Web-Content/common.txt

```

The scan successfully discovered a hidden directory named `.git`. This indicates that the developer accidentally deployed the entire Git version control folder to the public web server.

## 3. Exploitation (source code recovery)

An exposed `.git` folder is a critical vulnerability because it contains the entire history, source code, and potentially hardcoded credentials of the application.

Instead of downloading the files one by one manually, we used a specialized tool called `git-dumper` to automatically download the entire repository to our local machine:

```
git-dumper http://10.114.129.227:8080/.git/ day2

```

Once the repository was downloaded, we navigated into the `day2` directory and inspected the recovered files. By reading the `README.md` file left in the repository, we found our target.

## 4. Mitigation (how to fix it)

Exposing a `.git` folder can lead to a complete application compromise. To prevent this, system administrators and developers should:

+ **Never deploy `.git` folders to production:** Use proper deployment pipelines (CI/CD) that only copy the necessary compiled application files to the live server, leaving the version control files behind.
+ **Restrict web server access:** Configure the web server to explicitly deny all web requests targeting any folder or file starting with a dot (`.git`, `.env`, `.ssh`).
